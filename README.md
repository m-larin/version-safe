## Что это

**VersionSafe.ps1** — PowerShell-скрипт для создания версионных резервных копий папки на другой диск. Каждый запуск создаёт новый снимок с меткой времени. Неизменённые файлы не копируются заново, а связываются **жёсткими ссылками** (hard links) с предыдущим снимком. Это даёт колоссальную экономию места: новая копия занимает ровно столько, сколько изменилось с прошлого раза.

Дополнительно реализованы:
- **GFS-ротация** (Grandfather-Father-Son) — гибкое управление сроком хранения копий.
- **Поиск и восстановление разорванных ссылок** — файлов, которые должны быть ссылками, но хранятся отдельными копиями.
- **Защита от типичных ошибок** — рекурсия, отсутствие диска, неподдерживаемая ФС, повторный запуск, нехватка места.

## Возможности

| Возможность | Описание |
|---|---|
| 🕒 **Версионные снимки** | Каждая копия в отдельной папке с меткой времени `yyyy-MM-ddTHH-mm-ss`. |
| 🔗 **Дедупликация** | Неизменённые файлы связываются жёсткими ссылками — экономия места до 90%+. |
| 📦 **GFS-ротация** | Отдельно настраивается хранение дневных, недельных, месячных и годовых копий. |
| 🔍 **Проверка ссылок** | Поиск файлов, которые хранятся отдельной копией вместо жёсткой ссылки. |
| 🛠️ **Восстановление ссылок** | Такие копии заменяются жёсткими ссылками после сверки содержимого (SHA-256). |
| 📝 **Логирование** | Полный транскрипт каждого запуска сохраняется в корень папки назначения. |
| 📊 **Статистика** | Отчёт о количестве скопированных файлов, ссылок и сэкономленном месте. |
| 🧪 **`-WhatIf`** | Тестовый прогон: план снимка и ротации без изменений на диске. |
| 🛡️ **Защита от ошибок** | Проверки рекурсии и поддержки ссылок, блокировка повторного запуска, отмена снимка при нехватке места. |

## Как это работает

### Принцип дедупликации

При создании нового снимка для каждого файла проверяется, изменился ли он с прошлого раза (по размеру и времени изменения):

- **Изменился** → файл копируется заново.
- **Не изменился** → создаётся жёсткая ссылка на файл из предыдущего снимка. Физически данные не дублируются, новый файл не занимает места.

### Схема на диске

```
D:\Backups\
├── 2026-09-27T03-00-00\      ← старый снимок
│   └── Documents\
│       └── report.docx       ← оригинал (занимает место)
├── 2026-09-28T03-00-00\      ← следующий снимок
│   └── Documents\
│       └── report.docx       ← жёсткая ссылка (0 байт)
├── 2026-09-29T03-00-00\      ← сегодняшний снимок
│   └── Documents\
│       └── report.docx       ← жёсткая ссылка (0 байт)
├── VersionSafe-2026-09-27T03-00-00.log
├── VersionSafe-2026-09-28T03-00-00.log
└── VersionSafe-2026-09-29T03-00-00.log
```

Все три `report.docx` указывают на один и тот же блок данных. Если файл не менялся — место занято один раз.

### Жизненный цикл запуска

1. Проверяется, что источник и назначение не пересекаются, и что в эту папку назначения не пишет другой экземпляр скрипта (файл `VersionSafe.lock`).
2. В папке назначения создаётся пробная жёсткая ссылка. Если не получилось — скрипт переключается в режим полного копирования.
3. Удаляются папки `*.inProgress`, оставшиеся от прерванных запусков.
4. (Если указан `-VerifyLinks`) ищутся и восстанавливаются разорванные ссылки.
5. Создаётся папка `<дата>.inProgress`, в неё копируются изменённые файлы, неизменённые связываются ссылками.
6. При успехе папка переименовывается в `<дата>`. При сбое (например, закончилось место) папка `.inProgress` **удаляется**, а старые снимки не трогаются.
7. **Только после успешного снимка** выполняется GFS-ротация и очистка старых логов.

Символические ссылки и точки соединения (junction) внутри источника **пропускаются**: иначе в снимок попали бы данные из других папок или возник бы бесконечный цикл (например, служебные `Application Data` и `Мои документы` в профиле пользователя).

## Требования

### Обязательные

- **Windows 10/11** или Windows Server 2016+.
- **PowerShell 5.0+** (встроен в Windows 10/11) или PowerShell 7.
- **Диск назначения с поддержкой жёстких ссылок** — для дедупликации:

| Файловая система | Поддержка ссылок |
|---|---|
| NTFS | ✅ Да |
| ReFS | ⚠️ Зависит от версии Windows и ReFS |
| FAT16 / FAT32 / exFAT | ❌ Нет |
| Сетевая папка (SMB) | ⚠️ Зависит от сервера |

Поддержка проверяется при каждом запуске пробной ссылкой прямо в папке назначения. Если ссылки не работают, скрипт сам переключается в режим полного копирования (как с `-NoHardLinks`) и сообщает об этом.

### Рекомендуемые

- Права администратора — если нужно сохранять файлы, к которым у обычного пользователя нет доступа. Для самих жёстких ссылок права администратора не нужны.
- Внешний или второй физический диск для бэкапа.
- Отключение диска от системы, когда бэкап не выполняется (защита от шифровальщиков).

## Установка

### 1. Сохраните скрипт

Скопируйте `VersionSafe.ps1` в удобное место, например:

```
C:\Scripts\VersionSafe.ps1
```

Скрипт сохранён в кодировке **UTF-8 с BOM**. Если будете его редактировать, сохраняйте в той же кодировке: без BOM Windows PowerShell 5.1 неправильно читает русский текст и выдаёт синтаксические ошибки.

### 2. Разрешите выполнение скриптов

Один раз в PowerShell:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### 3. Проверьте работу вручную

```powershell
cd C:\Scripts
.\VersionSafe.ps1 -SourcePath C:\Users\jdoe -DestinationPath D:\Backups -WhatIf
```

Параметр `-WhatIf` покажет, что скрипт собирается делать, но не внесёт изменений.

### 4. Первый реальный запуск

```powershell
.\VersionSafe.ps1 -SourcePath C:\Users\jdoe -DestinationPath D:\Backups
```

Справка по параметрам: `Get-Help .\VersionSafe.ps1 -Full`.

## Быстрый старт

### Простой бэкап

```powershell
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups
```

### Бэкап с GFS-ротацией

```powershell
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups `
    -DailyCount 7 -WeeklyCount 4 -MonthlyCount 12 -YearlyCount 5
```

### Бэкап с проверкой и восстановлением ссылок

```powershell
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups -RepairBrokenLinks
```

### Полное копирование (без ссылок)

```powershell
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath E:\Backup -NoHardLinks
```

### Хранить всё, без ротации

```powershell
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups -RotationDisabled
```

## Параметры

### Основные

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `-SourcePath` | string | ✅ Да | Папка-источник. Можно передать через конвейер (одну). |
| `-DestinationPath` | string | ✅ Да | Папка назначения на другом диске. Создаётся при отсутствии. Не может совпадать с источником, находиться внутри него или содержать его. |

### Поведение

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `-FailIfOldBackupsAreMissing` | switch | off | Прервать работу, если нет ни одного готового снимка. Защита от запуска без подключённого диска. Папка назначения в этом случае не создаётся. |
| `-NoHardLinks` (alias `-FullCopy`) | switch | off | Полное копирование без ссылок. Для FAT32, exFAT, сетевых дисков. Включается автоматически, если ссылки не поддерживаются. |
| `-NoLogging` | switch | off | Не создавать лог-файл. |
| `-NoStatistics` | switch | off | Не выводить статистику. |
| `-RotationDisabled` | switch | off | Полностью отключить GFS-ротацию. |

### GFS-ротация

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `-DailyCount` | int | 7 | Сколько хранить самых свежих копий. |
| `-WeeklyCount` | int | 4 | Сколько хранить недель (по одной копии из недели). |
| `-MonthlyCount` | int | 12 | Сколько хранить месяцев (по одной копии из месяца). |
| `-YearlyCount` | int | 5 | Сколько хранить лет (по одной копии из года). |
| `-LogRetentionDays` | int | 0 | Сколько дней хранить логи неудачных запусков. 0 — хранить все. Лог успешного снимка удаляется вместе со снимком. |

### Проверка ссылок

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `-VerifyLinks` | switch | off | Искать разорванные ссылки перед созданием снимка. |
| `-VerifyLinksOlderThanDays` | int | 0 | Проверять только снимки старше N дней. 0 — все. |
| `-RepairBrokenLinks` | switch | off | Восстанавливать найденные разорванные ссылки. Включает `-VerifyLinks`. |

В режиме без жёстких ссылок проверка не выполняется: там все файлы и так хранятся копиями.

### Прочее

| Параметр | Описание |
|---|---|
| `-WhatIf` | Показать план снимка, ротации и восстановления без реальных изменений. |
| `-Confirm` | Спрашивать подтверждение перед каждым удалением (снимков, логов, `.inProgress`) и восстановлением ссылки. |
| `-Verbose` | Подробный вывод: каждый скопированный и связанный файл, пропущенные ссылки. |
| `-InformationAction SilentlyContinue` | Скрыть информационные сообщения (предупреждения и ошибки останутся). |

## Коды завершения

| Код | Значение |
|---|---|
| `0` | Снимок создан без ошибок. |
| `1` | Снимок не создан: ошибка параметров, диск не подключён, скрипт уже запущен, закончилось место и т.п. |
| `2` | Снимок создан, но часть файлов или папок прочитать не удалось (например, файлы, занятые другими программами). Подробности — в логе. |

Коды удобно отслеживать в Планировщике заданий (колонка «Результат последнего запуска»).

## Ротация GFS

**GFS (Grandfather-Father-Son)** — классическая схема хранения резервных копий, при которой копии классифицируются по уровню значимости. Скрипт хранит **объединение** якорных копий всех уровней — одна копия может быть якорем для нескольких категорий сразу.

Ротация выполняется только после успешного создания нового снимка. Если снимок не удался, старые копии не удаляются.

### Как выбираются якоря

| Уровень | Что хранится |
|---|---|
| **Daily** | N самых свежих копий. |
| **Weekly** | По одной копии из каждой недели (самая свежая в неделе). Недели считаются по ISO 8601 — с понедельника, неделя на стыке годов не делится. |
| **Monthly** | По одной копии из каждого месяца (самая свежая в месяце). |
| **Yearly** | По одной копии из каждого года (самая свежая в году). |

### Пример

Параметры: `-DailyCount 7 -WeeklyCount 4 -MonthlyCount 12 -YearlyCount 5`, ежедневные бэкапы в течение 3 лет.

Останутся:
- 7 последних копий (за неделю),
- последние копии 4 последних недель,
- последние копии 12 последних месяцев,
- последние копии каждого года — их 3, потому что архиву 3 года.

**Реально останется около 20 копий**, а не 7+4+12+5 = 28, потому что якоря пересекаются (например, самая свежая копия — одновременно дневная, недельная, месячная и годовая).

### Отключение ротации

```powershell
-RotationDisabled
```

или

```powershell
-DailyCount 0 -WeeklyCount 0 -MonthlyCount 0 -YearlyCount 0
```

## Проверка разорванных ссылок

У жёсткой ссылки в NTFS нет «цели», которая могла бы пропасть: все имена файла равноправны, и данные существуют, пока есть хотя бы одно имя. Поэтому «битых» ссылок не бывает. Но ссылка может быть **разорвана** — файл, который не менялся, хранится в снимке отдельной копией. Так бывает:
- при переносе снимков инструментом, не поддерживающим ссылки (обычное копирование в Проводнике);
- если ссылку не удалось создать при бэкапе (например, достигнут предел NTFS в 1023 ссылки на один файл — тогда файл копируется);
- после восстановления снимков из другой резервной копии.

Данные при этом целы — теряется только место на диске.

### Что проверяется

Для каждого снимка (кроме самого старого) файл считается разорванной ссылкой, если в предыдущем снимке есть файл с тем же путём, тем же размером и временем изменения, но это **другой файл** на диске (сравниваются идентификаторы файлов NTFS).

### Режимы работы

```powershell
# Только проверка, без восстановления
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups -VerifyLinks

# Проверка + восстановление
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups -RepairBrokenLinks

# Проверять только снимки старше 30 дней
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups `
    -RepairBrokenLinks -VerifyLinksOlderThanDays 30
```

### Как работает восстановление

1. Содержимое обоих файлов сравнивается по SHA-256.
2. Если совпадает — рядом создаётся жёсткая ссылка на файл из предыдущего снимка, и только потом копия заменяется ею. В любой момент в снимке остаётся файл с данными.
3. Если содержимое различается — это разные версии с одинаковыми размером и временем. Файл не трогается, выводится предупреждение.

Снимки обрабатываются от старых к новым, поэтому цепочка разорванных ссылок собирается обратно в один файл за один проход.

## Использование из Планировщика заданий

### Способ 1: через GUI

1. Откройте **Планировщик заданий** (`taskschd.msc`).
2. **Создать задачу** (не «простую задачу»).
3. Вкладка **Общие**:
   - Имя: `VersionSafe Daily Backup`.
   - ✅ «Выполнять с наивысшими правами».
   - ✅ «Выполнять независимо от того, вошёл пользователь в систему или нет».
4. Вкладка **Триггеры** → **Создать**:
   - Ежедневно, например, в 03:00.
5. Вкладка **Действия** → **Создать**:
   - Действие: «Запуск программы».
   - Программа: `powershell.exe`
   - Аргументы:
     ```
     -NoProfile -ExecutionPolicy Bypass -File "C:\Scripts\VersionSafe.ps1" -SourcePath "C:\Data" -DestinationPath "D:\Backups" -DailyCount 7 -WeeklyCount 4 -MonthlyCount 12 -YearlyCount 5 -FailIfOldBackupsAreMissing -NoStatistics
     ```
6. Вкладка **Условия**:
   - ❌ Снять «Запускать только при питании от электросети» (если ноутбук).
7. Вкладка **Параметры**:
   - ✅ «Если задача уже выполняется, то: Не запускать новую».

### Способ 2: через командную строку

```cmd
schtasks /Create /TN "VersionSafe Daily Backup" ^
    /TR "powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups -DailyCount 7 -WeeklyCount 4 -MonthlyCount 12 -YearlyCount 5 -FailIfOldBackupsAreMissing -NoStatistics" ^
    /SC DAILY /ST 03:00 /RL HIGHEST /F
```

### Рекомендации

- Указывайте `-FailIfOldBackupsAreMissing` (после первого ручного запуска) — это защитит от запуска бэкапа, когда внешний диск не подключён.
- Следите за кодом завершения: `2` означает, что часть файлов не попала в снимок.
- Запускайте `-RepairBrokenLinks` при необходимости — например, после переноса архива на другой диск.
- Не запускайте бэкап слишком часто — раз в день достаточно для большинства задач.

## Примеры

### 1. Ежедневный бэкап с ротацией

```powershell
.\VersionSafe.ps1 -SourcePath C:\Users\jdoe -DestinationPath D:\Backups `
    -DailyCount 7 -WeeklyCount 4 -MonthlyCount 12 -YearlyCount 5
```

Оставит 7 дневных, 4 недельных, 12 месячных, 5 годовых копий (с пересечениями).

### 2. Только дневные и месячные

```powershell
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups `
    -DailyCount 14 -WeeklyCount 0 -MonthlyCount 6 -YearlyCount 0
```

### 3. Хранить всё

```powershell
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups -RotationDisabled
```

### 4. Для exFAT-диска или сетевой шары

```powershell
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath E:\Backup -NoHardLinks
```

Полное копирование — каждая версия занимает полный объём.

### 5. Бэкап с восстановлением ссылок

```powershell
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups `
    -RepairBrokenLinks -DailyCount 7 -MonthlyCount 12
```

### 6. Тестовый прогон

```powershell
.\VersionSafe.ps1 -SourcePath C:\Data -DestinationPath D:\Backups `
    -RepairBrokenLinks -WhatIf
```

Покажет, сколько файлов было бы скопировано и связано, какие ссылки были бы восстановлены и какие снимки удалены ротацией. На диске ничего не меняется.

### 7. Через конвейер

```powershell
Get-Location | .\VersionSafe.ps1 -DestinationPath D:\Backups
Get-Item "C:\Data" | .\VersionSafe.ps1 -DestinationPath D:\Backups
```

За один запуск сохраняется одна папка. Если передать несколько, скрипт завершится с ошибкой: снимки разных источников в одной папке назначения мешали бы дедупликации и ротации.

## Структура бэкапа

```
D:\Backups\
├── 2026-09-01T03-00-00\           ← снимок
│   ├── Documents\                 ← структура повторяет источник
│   │   ├── report.docx            ← оригинал или ссылка
│   │   └── notes.txt
│   └── Photos\
│       └── img001.jpg
├── 2026-09-02T03-00-00\
│   └── ...
├── VersionSafe-2026-09-01T03-00-00.log   ← лог запуска, создавшего снимок
├── VersionSafe-2026-09-02T03-00-00.log
├── VersionSafe-2026-09-15T03-00-00.log   ← лог неудачного запуска (снимка нет)
└── VersionSafe.lock                      ← существует только во время работы
```

### Формат имён снимков

```
yyyy-MM-ddTHH-mm-ss
```

Например: `2026-09-29T03-00-00`.

Лексикографическая сортировка имён совпадает с хронологической — это важно для ротации.

### Логи

- Лог каждого запуска: `VersionSafe-<дата>.log` в корне назначения. Внутрь снимка лог не кладётся, чтобы не затереть одноимённый файл из источника.
- Лог успешного снимка удаляется вместе со снимком при ротации.
- Логи неудачных запусков удаляются через `-LogRetentionDays` дней (0 — хранить все).
- В режиме `-WhatIf` лог не создаётся.

## Безопасность

### ⚠️ Жёсткие ссылки не защищают от изменения данных

Это ключевое ограничение. Если открыть файл **внутри снимка** и изменить его на месте, изменение затронет **все снимки**, ссылающиеся на тот же файл. Не редактируйте файлы в снимках — копируйте их наружу.

### ✅ Что скрипт защищает

- **От случайного удаления** — старые снимки не трогаются до ротации.
- **От изменения файлов в источнике** — изменённый файл копируется в новый снимок отдельно, старые версии не затрагиваются.
- **От потери структуры** — каждый снимок содержит полное дерево папок.
- **От сбоя диска-источника** — данные есть на другом диске.

### ❌ Чего скрипт не защищает

- **От шифровальщика с доступом к диску назначения.** Он может испортить файлы прямо в снимках. Нужна offsite-копия или отключаемый диск.
- **От физического повреждения диска назначения.** Нужна вторая копия.
- **От удаления диска назначения.** Нужна вторая копия.

### Рекомендации

1. **Offsite-копия.** Раз в неделю/месяц копируйте один из снимков на внешний диск и **физически отключайте его**. Это единственная надёжная защита от шифровальщиков и физических катастроф.
2. **Разные диски.** Источник и назначение — всегда разные физические диски.
3. **Проверка на VirusTotal.** Перед первым запуском загрузите скрипт на [virustotal.com](https://www.virustotal.com/).
4. **Проверка восстановления.** Раз в квартал восстанавливайте пару файлов из бэкапа — убедитесь, что они открываются.
5. **Мониторинг.** Следите за кодом завершения задачи и предупреждениями в логах.

## Ограничения

| Ограничение | Описание |
|---|---|
| **Дедупликация только на NTFS** (и других ФС с жёсткими ссылками) | На FAT32 и exFAT скрипт автоматически переходит на полное копирование. |
| **Сетевые папки** | Ссылки проверяются пробной ссылкой при запуске; если не работают — полное копирование. |
| **Один источник за запуск** | Для нескольких источников запускайте скрипт отдельно, с разными папками назначения. |
| **Сравнение по размеру и времени изменения** | Если файл изменён, но сохранил размер и время — изменение не будет замечено. |
| **Занятые файлы не копируются** | Файлы, открытые другими программами без общего доступа (например, `NTUSER.DAT`, базы Outlook), пропускаются с предупреждением, код завершения — `2`. Теневые копии (VSS) не используются. |
| **Символические ссылки и junction пропускаются** | Их содержимое не попадает в снимок. |
| **Предел 1023 ссылки на файл (NTFS)** | Если файл не менялся более 1023 снимков подряд, он будет скопирован заново — это штатно. |
| **Нет сжатия и шифрования** | Снимки хранятся как есть. Для шифрования используйте BitLocker на диске назначения. |
| **Нет дельта-копирования внутри файла** | Если изменился 1 байт в 1 ГБ файле — файл копируется целиком. |
| **Проверка ссылок — медленная** | Читаются все файлы всех снимков, при восстановлении — ещё и хешируются. Используйте `-VerifyLinksOlderThanDays`. |
| **Нужен режим FullLanguage** | Скрипт компилирует небольшой C#-помощник (`Add-Type`); в режиме Constrained Language он не запустится. |

## FAQ

### Чем это отличается от `rsync --link-dest`?

Идея та же: неизменённые файлы связываются жёсткими ссылками. Отличия:
- `rsync` — инструмент Linux/macOS, VersionSafe работает в Windows без дополнительных программ.
- VersionSafe сам именует снимки, ведёт лог каждого запуска и выполняет GFS-ротацию; с `rsync` это делается внешними скриптами.
- VersionSafe умеет находить и восстанавливать разорванные ссылки.

### Почему нельзя просто использовать `robocopy /MIR`?

`robocopy /MIR` делает **зеркало**: удаляет в назначении то, чего нет в источнике, и перезаписывает более новые файлы. Это опасно:
- Если вирус зашифрует файл в источнике — он затрёт здоровый бэкап.
- Если вы случайно удалите файл — он исчезнет и из бэкапа.

VersionSafe создаёт **независимые снимки**; старые снимки удаляются только ротацией.

### Можно ли запускать на сетевой диск?

Да, с оговорками:
- Жёсткие ссылки на SMB могут не работать — скрипт это определит и перейдёт на полное копирование. Можно сразу указать `-NoHardLinks`.
- Скорость будет ниже, чем на локальном диске.

### Что будет, если бэкап прервётся?

Незавершённый снимок останется в папке `<дата>.inProgress`. Он не считается готовым и не используется как основа для следующего снимка. При следующем запуске скрипт удалит его автоматически.

### Что будет, если закончится место?

Снимок отменяется: папка `.inProgress` удаляется, старые снимки не трогаются, код завершения — `1`. Уменьшите счётчики ротации или освободите место.

### Можно ли запустить два бэкапа одновременно?

В одну папку назначения — нет: второй запуск завершится с ошибкой, пока первый держит `VersionSafe.lock`. В разные папки — можно.

### Как восстановить файл?

Просто скопируйте его из нужного снимка:

```powershell
Copy-Item "D:\Backups\2026-09-27T03-00-00\Documents\report.docx" "C:\Restore\"
```

### Как удалить старые снимки вручную?

```powershell
Remove-Item "D:\Backups\2026-09-01T03-00-00" -Recurse -Force
```

Удалять снимки можно в любом порядке: данные файла сохраняются, пока на него ссылается хотя бы один снимок. Либо запустите скрипт с новыми параметрами ротации — он удалит лишнее.

### Почему скрипт удаляет старые снимки?

По умолчанию ротация **включена** (7/4/12/5). Если вы хотите хранить всё — используйте `-RotationDisabled` или задайте все счётчики равными 0.

### Как проверить, что жёсткие ссылки работают?

```powershell
fsutil hardlink list "D:\Backups\2026-09-29T03-00-00\Documents\report.docx"
```

Команда выведет все имена файла — по одному на каждый снимок, где он не менялся. Также можно запустить скрипт с `-Verbose` — он покажет, какие файлы связываются ссылками.

### Совместим ли скрипт с PowerShell 7?

Да, скрипт работает и в Windows PowerShell 5.1, и в PowerShell 7. `#Requires -Version 5.0` — минимальное требование.

### Почему в Windows PowerShell 5.1 скрипт выдаёт синтаксические ошибки?

Скорее всего, файл был пересохранён в UTF-8 без BOM. Пересохраните его в кодировке «UTF-8 with BOM» (в VS Code: строка состояния → кодировка → Save with Encoding).

### Что делать, если антивирус ругается?

PowerShell-скрипты часто вызывают ложные срабатывания. Проверьте файл на [VirusTotal](https://www.virustotal.com/). Если срабатывание ложное — добавьте в исключения. Если нет — не используйте.
